# Yourkly Artifacts — App Flow

How a person goes from never having heard of this to being a happy user.
This is the master flow. Every screen we build must serve one of these steps.

## 1. Arrive — the landing page (`/`)

A first-time visitor (or contest judge) lands here.
- Stork + wordmark, headline, one plain paragraph: what Yourkly Artifacts is.
  (Version control for people who never want to hear the word git, rebuilt on
  Cloudflare, now with a team of AI helpers.)
- Meet the team: the fixer, the builder, the polisher, each with its mascot
  and one line on what it does.
- How it works in 3 steps.
- One button: "Start a project." That is the whole call to action.
- Status: IN BUILD.

## 2. Sign up — DECISION NEEDED

Recommendation: no account needed to try it. Click "Start a project,"
name it, and you are in. Judges will not sign up for anything, and the
demo must work in one click.

When someone wants to keep their projects across devices, ask for email
then (code sent to their inbox, the way the main Yourkly does it).

NaLonni to approve: try-first with email later, yes or no?

## 3. Start a project

- Give the project a name.
- We set up a safe place for it and save the first version.
- Land in the project view.
- Status: BUILT.

## 4. Work on files

- File list down the side. "New file" button. Click a file to open it.
- A plain writing editor. Write, save, keep going.
- Nothing here should need explaining. If it does, the design is wrong.
- Status: BUILT.

## 5. Save points (versions)

- "Save this version" asks for a plain-language label: what changed.
- History shows every version with its label and date, newest first.
- "Go back to this version" restores it. Current work is never lost;
  going back just saves where you were first.
- Status: BUILT.

## 6. Send in the agents

- From any project: "Send in the agents."
- Describe what you need in plain words (or pick a suggested task).
- Each agent gets its own private copy of the project and works at the
  same time. You see each one working, with its mascot, so you always
  know who is doing what.
- Status: BUILT.

## 7. Compare

- When the agents finish, their work appears side by side.
- Each one is explained in plain words: what it changed and why.
- Each card shows the agent's mascot so you can tell them apart at a glance.
- Status: BUILT.

## 8. Keep one

- "Keep this one" makes that agent's version the project's current version.
- The other copies stay saved. Nothing is thrown away.
- You are back in the project view, on the winning version.
- Status: BUILT.

## 9. Share — LATER (after the contest)

- Share a project link, publish a version. Out of contest scope.
- Do not build this before the 14th.

## Rules for this flow

- Every step must work with zero explanation. Plain words only.
- No step may require knowing what git is.
- The main Yourkly logo is never redesigned. Agent mascots follow the
  basket concept (stork carries a woven basket of files; the basket's
  contents show the agent's job).
